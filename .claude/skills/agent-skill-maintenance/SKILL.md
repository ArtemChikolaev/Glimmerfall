# Поддержка общих скиллов

Сначала прочитай [принципы](../../../docs/ai/PRINCIPLES.md) и [каталог](../../../docs/ai/INDEX.md). Канонические тексты — `.claude/skills`; адаптеры не содержат редактируемых копий.

1. Зафиксируй рабочий diff и сравни все варианты затронутого скилла, включая tools и references. Не заменяй копию ссылкой до проверки её уникальных полезных правил.
2. Для нового скилла укажи наблюдённую проблему, триггер, повторяемую процедуру, пробел существующих скиллов и ожидаемый результат. Если это один дополнительный пункт — расширь ближайший скилл.
3. Проверь технические утверждения по коду, внешние правила — по официальным источникам. Различай Agent Skills standard, Claude Code, Claude.ai и Codex. Не закрепляй имена моделей, личные пути и исторические числа как вечные требования.
4. Короткое описание отвечает «когда», тело — «как». Детали выноси в references только при реальной необходимости. Инструмент добавляй для проверяемой повторяемой операции; не создавай пустые каталоги или скрипт ради формы.
5. Обнови относительные ссылки адаптеров (`.agents/skills`, `.codex/skills`) и INDEX. Проверь README и документы, на которые ссылается процедура: устаревшая команда там вернёт исправленную ошибку при следующем discovery. Не расширяй permissions и не обещай работу hooks в другом клиенте без проверки.
6. Выполни команды проверки из PRINCIPLES, позитивные и негативные trigger-примеры и сценарий применения. Статический валидатор не доказывает реальную автоматическую активацию модели.
7. В отчёте отдели статическую проверку, ручную проверку маршрутизации и настоящий запуск в каждом клиенте. Укажи, где нужен новый сеанс, чтобы клиент перечитал каталог.

Выход: один источник инструкций, проверенные ссылки и YAML, сценарии регрессии и честные ограничения проверки.
