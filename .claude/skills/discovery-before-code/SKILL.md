# Сначала найди готовое

1. Уточни для себя ожидаемое поведение и прочитай материалы пользователя. Объём поиска соразмерен изменению.
2. Найди карту области в [README](../../../README.md), [PRD](../../../docs/PRD.md) и ADR в `docs/adr/`. Читай релевантные разделы, а не все документы целиком.
3. Используй `rg --files` и `rg` по нескольким смысловым терминам. Проверь определения, вызовы и тесты ближайшего аналога. Отсутствие точного имени не доказывает отсутствие решения.
4. Выбери точку расширения по слоям [ADR 0002](../../../docs/adr/0002-tech-stack.md): правило игры — `sim/`, а не скрипт Godot; отображение — `game/`; данные — `content/` и его схема; конвейер ассетов — `tools/`. Новый источник благословений — через общий конвейер предложений; новое поле врага — через общий default.
5. Кратко зафиксируй найденное: «Переиспользую A и B; добавляю Q, поскольку найденный C не покрывает …». Если аналога нет, укажи область поиска без заявления о доказанном отсутствии во всём проекте.

Расширение почти подходящего модуля и выбор между обратимыми вариантами обычно входят в поручение — не останавливай работу из-за этого. Важную продуктовую неоднозначность обработай через [plan-first-communication](../plan-first-communication/SKILL.md).

Не клонируй систему, сцену, компонент или формулу ради удобного имени. Правила сима — [sim-invariants](../sim-invariants/SKILL.md), отклик и эффекты — [game-feel-vfx](../game-feel-vfx/SKILL.md).
