# CLAUDE.md — Glimmerfall

Контекст, который нужен **всегда** при работе над проектом. Пошаговые процедуры — в скиллах (`.claude/skills/`, авто-активация по `description`); каталог и маршрутизация — [docs/ai/INDEX.md](docs/ai/INDEX.md); принципы ведения скиллов — [docs/ai/PRINCIPLES.md](docs/ai/PRINCIPLES.md).

## Проект
**Glimmerfall** (рабочее название до проверки товарного знака) — изометрический пиксельный survivors-ARPG в рамке Death Must Die с собственным крючком: игрок драфтит **отряд из трёх героев** с «сыгранностью» и переключается между ними посреди орды. Сеттинг — отряд фонарщиков несёт общий фонарь через мир, который поглощает Тьма. Оригинальная IP, коммерческий релиз.
- Продукт — [docs/PRD.md](docs/PRD.md); решения — [ADR 0001 концепция](docs/adr/0001-concept-and-scope.md), [ADR 0002 стек](docs/adr/0002-tech-stack.md), [ADR 0003 арт](docs/adr/0003-art-direction.md); план — [docs/BACKLOG.md](docs/BACKLOG.md); исходное исследование — [docs/research/](docs/research/README.md).
- Статус: **препродакшн** (этапы 0–1 бэклога). Кода игры ещё нет — первые строки появятся в технических спайках.

## Правило 0 — Reuse-first (главное)
Перед новым кодом (модуль, класс, сцена, скрипт, формат данных) — докажи, что готового аналога нет: `README.md`, `docs/PRD.md`, ADR, существующий код. Формула: «НЕ создаю X, Y — есть A, B; создаю только Q». Процесс — скилл `discovery-before-code`.

## Столпы (сверяй с ними каждую фичу)
1. **Живая и плавная.** «Нативность» в понимании владельца — прежде всего ощущение живой игры: много анимаций, огонь и молнии, 60+ fps без рывков. У каждого действия есть замах, удар и след; у каждого врага — реакция и эффектная смерть. Мёртвый экран — дефект, а не полиш на потом. Скилл `game-feel-vfx`.
2. **Угроза с первой минуты.** Стоять AFK — смерть даже на базовой сложности; враги заставляют двигаться. Проверяется ботом, а не ощущением. Скиллы `encounter-design`, `balance-harness`.
3. **Отряд.** Разнообразие растёт комбинаторно (тройки героев, пары покровителей), а не числом анимированных персонажей. Короткий ростер с глубокими китами вместо широкого мелкого.
4. **Честная проверяемость.** Детерминированный сим даёт реплеи, дейлики, призраков и рекорды, которые нельзя подделать. Скилл `sim-determinism`.
5. **Нативные сборки.** ПК (Windows/macOS/Linux) и Steam Deck — первыми; консоли и телефоны — второй волной. Управление под тач и сохранение в любой момент закладываются с первого дня.

## Архитектура (целевая, по ADR 0002)
- `sim/` — **чистый C#** без ссылок на движок: фиксированная точка, свой PRNG, тик 60 Гц, весь ввод игроков — через лог шагов. Тесты — `sim.tests/`, headless-бот и верификатор — `sim.cli/`.
- `game/` — Godot 4.7 (.NET): **только презентация** (рендер, интерполяция, VFX, звук, UI, ввод). Сим не знает о Godot; Godot читает снимки сима и отправляет ввод.
- `content/` — данные под JSON Schema; `tools/` — Blender/Python-конвейер спрайтов и утилиты; `server/` — Go (сиды дейликов, приём и ре-симуляция реплеев, trusted-лидерборды); `validator/` — тот же `Sim.dll` для проверки реплеев.
- Косметика **никогда** не влияет на сим и сид. Числа в UI считаются теми же функциями, что и в симе.

## Детерминизм (никогда не нарушать)
- В состоянии сима нет `float`/`double`: целочисленная фиксированная точка, тригонометрия — таблицы или полиномы. `System.Random`, RNG и физика движка запрещены; свой PRNG с потоком на подсистему.
- Изменил правила или коэффициенты → бампни версию баланса (несовместимые реплеи отказываются явно). Сдвиг порядка RNG → осознанная перегенерация golden с проверкой.
- Перф-оптимизация — только с профилем и бит-в-бит дайджестами до и после. Детали — скилл `sim-determinism`.

## IP и ассеты
- **Ничего от Valve/Dota** (имена, модели, звуки, иконки, «Aegis», Roshan, ранги Herald…Immortal) и **никаких share-alike-ассетов** (LPC и т. п.) — проект коммерческий.
- Генеративный ИИ — только для идей и временных заглушек: каждый такой файл вносится в реестр происхождения, релизная сборка с ним не собирается. В фирменных визуалах (герои, боссы, ключевой арт, капсула) ИИ нет. Для текста и кода ИИ-агенты — обычный инструмент.
- Секреты — только из env, не в коде и не в git.

## Процесс (правила владельца)
- Коммиты — прямо в `main`, без веток и PR; защита — проверки до коммита. **Push ≠ deploy:** после пуша дождись CI.
- Правки — через Edit, не `sed`; большие документы читай по разделам. Документы держим маленькими: бэклог ротируется по этапам, числа в документах генерируются или проверяются тестом.
- Статус ✅ в бэклоге — не доказательство: сверяйся с кодом и тестами.
- Скриншот владельца с дефектом обычно показывает класс проблемы — чини класс, а не экземпляр.
- «Что ещё добавить?» без «сделай» — запрос на список вариантов, а не на реализацию.

## Перед «готово»
Скилл `self-review-checklist`. Проверки соразмерны изменению: docs и скиллы — валидатор скиллов и `git diff --check`; C# — `dotnet build` и `dotnet test` (когда появятся проекты); Godot — headless-импорт и тесты сцен (когда появится проект); изменения сима — дайджесты и golden-реплеи.

## Сравнение с референсами
«Сравни с Death Must Die / Halls of Torment / Dead Cells», «чего не хватает», «как у них сделано» → скилл `reference-parity-audit`: поведение и ощущение, а не копирование; недоступное помечай `unknown`.

## Дисциплина скиллов
1. Повторяющуюся инструкцию — в скилл или CLAUDE.md, а не объяснять заново.
2. Скилл = `description` (когда брать) + инструкции; tools/references — по необходимости.
3. Узкие скиллы, не монолит; актуальный список — `docs/ai/INDEX.md`.
4. Заводим и уточняем скилл по реальной шишке. В конце сессии: «что забрать в скилл навсегда?»
