# BACKLOG — Glimmerfall

Этапы с критериями выхода. Статусы: ⬜ не начато · 🟨 в работе · ✅ сделано (с датой и доказательством). Статус — не доказательство: сверяйся с кодом и тестами. Закрытый этап сворачивается в итог из нескольких строк, чтобы бэклог не разрастался.

Сроки — ориентиры: команды из 1–5 человек выходили в ранний доступ за 7–13 месяцев.

## Этап 1 — Технические спайки (2–4 недели, параллельно)
Выход: кадр < 8 мс на Steam Deck в спайке орды; реплеи бит-в-бит на трёх ОС; бот проходит акт headless; мобильная сборка измерена.

- ⬜ G1.0 Окружение: Godot 4.7.x .NET, актуальный .NET SDK (на машине владельца сейчас 7.0 — для Godot 4.7 мало), Aseprite; пины версий в репозитории.
- ⬜ G1.1 Скелет решения: `sim/`, `sim.tests/`, `sim.cli/`, `game/`; джобы CI — `dotnet build`, `dotnet test`, headless-импорт Godot.
- ⬜ G1.2 Детерминизм: формат фиксированной точки, PRNG с потоками, хеш состояния; golden-реплеи в матрице CI Windows x64, Linux x64, macOS arm64 — скилл `sim-determinism`.
- ⬜ G1.3 Орда: 5 тыс. врагов и 2 тыс. снарядов из C#-сима в MultiMesh/RenderingServer с интерполяцией; замер кадра на Steam Deck.
- ⬜ G1.4 Мобайл: та же сцена на среднем Android и iPhone — кадр, размер сборки, запуск, нагрев. Провал → отчёт и решение по [ADR 0002](adr/0002-tech-stack.md) (Unity с тем же `Sim.dll`).
- ⬜ G1.5 Бот-харнесс: идеи `sim_arcade` из aegis-draft в `sim.cli` — политики «кайтер» и «AFK», карьерный режим, статистика по актам — скилл `balance-harness`.
- ⬜ G1.6 Steam: GodotSteam, глифы Steam Input, Steam Cloud, trusted-лидерборд через Go-сервер, реплей как UGC.
- ⬜ G1.7 Сервер: каркас на Go по образцу aegis-draft и .NET-валидатор в Docker — ре-симуляция реплея и сравнение хешей.

## Этап 2 — Стиль и арт-срез (2–4 недели)
Выход: измерены часы на анимацию, метрика мерцания в норме, читаемость при 300+ врагах, выбрана сетка спрайтов.

- ⬜ G2.1 Стиль-библия: мастер-палитра, рампы VFX, план светлоты, материальная культура UI — [ADR 0003](adr/0003-art-direction.md).
- ⬜ G2.2 Концепт-художник: тёрнэраунды героя, трёх врагов и босса; ключевой арт.
- ⬜ G2.3 Перенос ядра Blender-конвейера из aegis-draft (камера, свет, контур, квантование, нейтрализация root motion, QA-метрики) без Valve-импорта, плюс метрика мерцания — скилл `sprite-pipeline`.
- ⬜ G2.4 Срез: 1 герой в 8 направлениях с 6 анимациями, 3 врага, 1 босс, 1 тайлсет и ~20 фирменных эффектов (огонь, молния, мороз, яд, сияние; слои замах → удар → след → смерть) — скилл `game-feel-vfx`.
- ⬜ G2.5 Контроль: один враг вручную у художника — сравнение качества и часов с 3D-конвейером.
- ⬜ G2.6 Сравнение сеток 640×360 и 960×540 на одной сцене: Steam Deck, 1080p, телефон.

## Этап 3 — Вертикальный срез (6–8 недель)
Выход: живые плейтесты подтверждают «хочу ещё»; не меньше 80% проходят акт; AFK-бот умирает быстрее порога; есть телеметрия выбора и побед.

- ⬜ G3.1 Один акт на 8–10 минут: карта с «местами», босс, чекпоинт.
- ⬜ G3.2 Отряд: 3 героя, свап, ассист и связка, сыгранность пары; контрольный вариант «спутники рядом» — [PRD §5](PRD.md).
- ⬜ G3.3 Два покровителя с благословениями и дуэтом; один конвейер предложений.
- ⬜ G3.4 Угроза: враги, заставляющие двигаться с первой минуты; элита ко 2-й минуте; гейт AFK-бота в CI — скилл `encounter-design`.
- ⬜ G3.5 Зрелищность: полный слой отклика на все действия среза; прогон по «мёртвым местам».
- ⬜ G3.6 Сохранение в любой момент, базовая мета (1–2 разблокировки), экран смерти с прогрессом.
- ⬜ G3.7 Плейтесты: 5–10 живых игроков, протокол и выводы; решение по модели отряда.
