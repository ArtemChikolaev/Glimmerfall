# ADR 0002 — Стек: Godot 4.7 (.NET) поверх чистого C#-сима

**Статус:** принято условно 2026-10-26; окончательно — после спайков этапа 1 ([BACKLOG](../BACKLOG.md)).
**Основание:** [исследование 2026-10](../research/2026-10-pixel-roguelite-analysis.md), раздел «„Нативно“ — это Godot 4.7 с чистым C#-симом»; заметки — [движки](../research/notes/engine_tech_2026.md).

## Что значит «нативно»
Для владельца это прежде всего **ощущение**: живая, плавная игра с обилием анимаций и эффектов, 60+ fps без рывков. Нативные сборки (ПК, Steam Deck, консоли, телефоны) и Steamworks — средство. Браузерный стек aegis-draft сюда не подходит: путь на консоли закрыт (Vampire Survivors ради них ушёл с Phaser на Unity), Steam-оверлей ненадёжен, производительность орды упирается в потолок.

## Решение
- **Презентация — Godot 4.7.x (.NET).** MIT, без отчислений; текстовые сцены и ресурсы удобны агентам и git; headless CLI для импорта, тестов и экспорта; целочисленное масштабирование и 2D-батчинг. Прецеденты жанра — Halls of Torment, Brotato, Slay the Spire 2 (на C#).
- **Логика — `sim/`: чистый C# без ссылок на движок.** Целочисленная фиксированная точка (формат — Q16.16 или шире, с 64-битными промежуточными; выбирается в спайке детерминизма), табличная тригонометрия, свой PRNG с потоком на подсистему, тик 60 Гц, массивы структур с пулами, равномерная сетка коллизий, общий flow field к игроку, хеш состояния. Один и тот же `Sim.dll` используют тесты, headless-бот, верификатор реплеев и сервер.
- **Сервер — Go** (chi + Postgres, по образцу aegis-draft): сиды дейликов, приём реплеев, ре-симуляция .NET-воркером, trusted-запись в лидерборды Steam.
- **Steamworks** через GodotSteam: облачные сейвы, достижения, Steam Input, лидерборды с прикреплёнными реплеями, Steam Datagram Relay для онлайна.
- **Плавность:** рендер на частоте дисплея с интерполяцией между тиками сима; орда рисуется через MultiMesh/RenderingServer, а не тысячами нод; пулы и прогрев шейдеров и эффектов против рывков.
- **Версии:** минор Godot и .NET SDK фиксируются в репозитории; обновление — только за зелёным CI.

### Структура репозитория (целевая)
```
sim/         чистый C#: правила, сущности, фиксированная точка, PRNG, хеш состояния
sim.tests/   xUnit: юнит-тесты, golden-реплеи, матрица Windows x64 / Linux x64 / macOS arm64
sim.cli/     headless: бот-прогоны, карьерная симуляция, верификатор реплеев, бенч тиков
game/        Godot 4.7 .NET: презентация, VFX, звук, UI, ввод, платформенный слой
content/     JSON под JSON Schema; метаданные атласов из Blender
tools/       Blender и Python: рендер 3D → пиксели, упаковка атласов, QA спрайтов, валидаторы
server/      Go: дейлики, реплеи, лидерборды
validator/   .NET-воркер с тем же Sim.dll
```

## Рассмотренные варианты
| Стек | Почему не основной |
|---|---|
| Unity 6.3 LTS + C#-сим или Photon Quantum | самый зрелый путь на консоли и телефоны, но консольные сборки требуют платный Pro на место, а сцены в YAML с GUID тяжелы для агентов. **Основной запасной путь** для презентации; выбор по умолчанию, если онлайн-ко-оп с откатом понадобится к запуску |
| MonoGame + C#-сим | всё в коде, но инструменты анимации, UI и частиц придётся строить самим — запасной путь второго порядка |
| Веб: TypeScript + PixiJS/Phaser + Tauri/Electron | нет пути на консоли, Steam-интеграция хрупкая |
| Bevy, LÖVE, свой движок | нет редактора или консолей либо неподъёмно для соло |

## Риски и как их снимаем
1. **C# на консолях у Godot:** у W4 Games статус beta, вышедших на консолях игр на Godot C# в источниках нет. → AOT-дружелюбный C# без рефлексии и кодогенерации; консольный спайк после доступа к девкитам; сим переносим, так что откат затронет только презентацию.
2. **C# на телефонах у Godot:** экспорт под Android и iOS помечен experimental (для Android нужен .NET 9+). Владелец хочет мобильную версию → **мобильный спайк в этапе 1** (BACKLOG G1.4): сим и орда на среднем Android и iPhone — кадр, размер сборки, запуск, нагрев. Провал → презентация на Unity с тем же `Sim.dll`.
3. **LLM путают API Godot 3 и 4:** версия закреплена в CLAUDE.md; C# вместо GDScript сужает поле путаницы; линт на устаревшие API.
4. **Две минорные версии Godot в год:** пин минора, обновление только за зелёным CI.

## Последствия
- Детерминизм не зависит от движка и компилятора: целочисленная математика одинакова на x64 и ARM64, под NativeAOT и в Go.
- Ко-оп добавляется без переделки ядра: ввод по игроку на тик, состояние снапшотится.
- Нужны .NET SDK новее установленного на машине владельца (сейчас 7.0) и Godot 4.7 .NET — ставятся в этапе 1 (BACKLOG G1.0).
- Хранение тяжёлых исходников арта (Git LFS или отдельное хранилище) решается до первого `.blend` (BACKLOG G0.7).
