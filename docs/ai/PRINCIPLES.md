# Поддержка проектных скиллов

## Один источник и узкая задача

Редактируем `.claude/skills`. В `.agents/skills` (каталог Codex) и совместимом `.codex/skills` создаём только относительную ссылку каталога `../../.claude/skills/<name>`. AGENTS.md — симлинк на CLAUDE.md; адаптер Cursor (`.cursor/rules/glimmerfall.mdc`) отсылает туда же.

Новый скилл нужен, когда есть наблюдённая повторяемая проблема и собственная процедура. Одно дополнение к проверке добавляется в существующий скилл. Отдельные версии под разные модели не нужны: различаются возможности клиентов и инструменты, а не проектные инварианты.

Стартовый набор (2026-10-26) перенесён из aegis-draft: процессные скиллы — почти дословно, предметные — переписаны движко-нейтрально из уроков его Аркады ([инвентаризация, раздел 3](../research/notes/aegis_draft_inventory.md)). Когда появится код, уточняй их по шишкам этого репозитория и убирай то, что не подтвердилось.

## Формат

- YAML: `name` совпадает с папкой, 1–64 символа, lowercase kebab-case; `description` коротко задаёт триггер и границу. Используем цитированную строку или корректный YAML block scalar.
- Локальная политика: description до 200 символов, SKILL.md до 500 строк. Это наш переносимый бюджет, а не универсальный лимит всех клиентов.
- Основной текст: вход → существенные действия → проверяемый результат. Редкие подробности выносим в references, когда это действительно сокращает основной путь.
- Обычные относительные Markdown-ссылки, и только на существующие файлы. Будущие пути кода (`sim/`, `game/`) пишем inline-кодом, а не ссылкой. Команды — от корня репозитория. Личные абсолютные пути не добавляем.
- tools, assets и agents/openai.yaml необязательны и не создаются ради шаблона. Существующие tools сохраняем: на них ссылается CI.
- Не закрепляем исторические количества, версии баланса и временные тарифы как вечные требования.
- Не добавляем обязательных согласований поверх авторизованного поручения.

## Проверка

Из корня репозитория, в отдельном Python-окружении (системный Python не менять):

```bash
python3 -m venv /tmp/glimmerfall-skill-check
/tmp/glimmerfall-skill-check/bin/pip install -r .claude/skills/agent-skill-maintenance/tools/requirements.txt
/tmp/glimmerfall-skill-check/bin/python .claude/skills/agent-skill-maintenance/tools/validate_skills.py
/tmp/glimmerfall-skill-check/bin/python -m unittest discover -s .claude/skills/agent-skill-maintenance/tools -p 'test_*.py'
git diff --check
```

Валидатор читает YAML настоящим парсером и проверяет имена и описания, ссылки в Markdown, полный состав адаптеров и INDEX. Абсолютные локальные ссылки (включая file URI) и абсолютные симлинки отклоняются: совпадение цели на машине автора не доказывает переносимость checkout. Доступность внешних URL, якоря и пути внутри кода он не проверяет — их проверяют по затронутой процедуре. Тот же набор команд гоняет CI.

[Trigger-набор](skill-trigger-cases.md) — качественные сценарии для всех скиллов, а не автоматический benchmark. Проверяй выбор по описаниям, затем поведение по тексту. При изменении триггеров повторяй и положительные, и соседние отрицательные случаи.

Для настоящего smoke открой новый сеанс каждого установленного клиента из корня проекта, проверь обнаружение каталога и попроси выполнить безопасный сценарий без записи. Если это не сделано, прямо укажи ограничение: статический PASS не означает автоактивацию.

## Совместимость и сопровождение

Claude Code читает `.claude/skills`, Codex документирует `.agents/skills` и симлинк-каталоги; `.codex/skills` сохранён для совместимости. Дубль обнаружения возможен, дубль редактирования запрещён. При подтверждённом переходе всех клиентов на `.agents/skills` legacy-адаптер можно удалить отдельной правкой вместе с валидатором.

`.claude/settings.json` и hooks — настройки Claude Code; в Codex они не выполняются. Переносимость проверок обеспечивают явные команды и CI.

В конце значимой сессии оцени, возникла ли повторяемая ошибка процесса. Обновляй скилл по доказательству, а не ради обязательной правки после каждого разговора. См. [agent-skill-maintenance](../../.claude/skills/agent-skill-maintenance/SKILL.md).
