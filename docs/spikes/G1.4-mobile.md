# G1.4 — Мобайл: Android и iPhone (2026-10-26)

**Итог:** сборки под оба телефона собираются из того же проекта и того же Sim.dll; замеров на устройствах ещё нет — нужны телефоны владельца. Решение по [ADR 0002](../adr/0002-tech-stack.md) (оставаться на Godot или уводить презентацию в Unity) — после замеров.

## Android
- Пресет `Android Bench` (arm64-v8a, тег `bench`): APK `build/android/glimmerfall-spike.apk`, **102 МБ** (движок + Mono-рантайм .NET + игра, без тримминга), minSdk 24, targetSdk 36, подпись — debug-ключом.
- **Находка:** шаблон экспорта Godot 4.7.2 принимает C#-проекты только под `net9.0`, а поддержка .NET 9 заканчивается 2026-11-10. Обход — условный `TargetFramework` для `GodotTargetPlatform == android` в `game/Glimmerfall.csproj`; SDK 10 собирает net9.0 сам. Дальше: Godot 4.8 с шаблоном под net10.0 или gradle-сборка — проверить с выходом 4.8.
- Эмулятор (Pixel 8 Pro API 34, без окна): C#-код стартует — `_Ready` отработал, Mono-рантайм и Sim.dll грузятся на arm64; кадры встают на выводе Vulkan в программном SwiftShader. Для замера эмулятор не годится.
- Сборка заново: в настройках редактора Godot указан JDK из Android Studio (`export/android/java_sdk_path`), ключ — через переменные:
  ```bash
  GODOT_ANDROID_KEYSTORE_RELEASE_PATH="$HOME/.android/debug.keystore" GODOT_ANDROID_KEYSTORE_RELEASE_USER=androiddebugkey GODOT_ANDROID_KEYSTORE_RELEASE_PASSWORD=android tools/godot.sh --headless --path game --export-release "Android Bench" ../build/android/glimmerfall-spike.apk
  ```

## iPhone
- Пресет `iOS Bench` выгружает Xcode-проект (`build/ios/Glimmerfall.xcodeproj`); C# компилируется **NativeAOT** в `Glimmerfall.dylib` 18,6 МБ без .NET-воркложда iOS.
- **Находка:** предупреждения AOT и тримминга внутри самого GodotSharp ломали ILC при `TreatWarningsAsErrors` — для ILC и тримминга это отключено в `game/Directory.Build.props`. Наш код предупреждений AOT не даёт: сим без рефлексии.
- Экспорт требует App Store Team ID (`application/app_store_team_id` в пресете) — его даёт аккаунт разработчика владельца; на устройство можно ставить и с бесплатной Personal Team (подпись на 7 дней).

## Тач-управление
`game/src/TouchControls.cs`: плавающий стик в левой половине экрана, кнопки DASH и SWAP справа, AUTO — автопилот вкл/выкл, выбор в модалке — тапом по колонке варианта. Сводится к тому же `InputFrame`. Собирается и проходит смоук, но **на сенсорном экране не проверено** — первая проверка будет на телефоне владельца (после замера: AUTO, затем играть вручную).

## Что сделать владельцу
| Шаг | Android | iPhone |
|---|---|---|
| Установить | `adb install build/android/glimmerfall-spike.apk` или файл на телефон и «установить» | в Xcode открыть `build/ios/Glimmerfall.xcodeproj` → Signing & Capabilities → своя Team → Run на подключённом iPhone (режим разработчика включён) |
| Замер кадра | сборка с тегом `bench` сама гонит 5 с прогрева и 60 с замера и оставляет отчёт на экране — снять скриншот | то же |
| Нагрев | после замера оставить игру на 10 минут (HUD показывает кадр), отметить тепло корпуса и просадку | то же |
| Запуск | секундомер от тапа по иконке до первого кадра орды | то же |
| Размер | размер APK уже известен (102 МБ); размер установленного приложения — в настройках телефона | размер .ipa из Xcode Archive |

Устройства для решения — «средний» Android (класс Snapdragon 7-й серии или Pixel a-серии) и iPhone поколения 2–3-летней давности.

## Критерии решения
- Кадр p99 ≤ 16,7 мс при орде, урезанной для телефона (предел орды и плотность VFX — по платформе, PRD §11), без перегрева за 10 минут.
- Размер сборки приемлем для премиум-порта (ориентир < 200 МБ после тримминга).
- Провал — отчёт и решение по ADR 0002: презентация на Unity с тем же `Sim.dll` (`netstandard2.1` уже грузится в Mono).
