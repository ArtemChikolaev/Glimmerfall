# G1.7 — Сервер: каркас и валидатор (2026-10-26)

**Итог:** каркас работает сквозь весь путь: дейлик → реплей → ре-симуляция тем же Sim.dll → очки и место в таблице. Postgres, вход через Steam и trusted-запись в лидерборды Steam — следующие шаги (зависят от [G1.6](G1.6-steam.md)).

## Что сделано
- `server/` — Go 1.26 по слоям aegis-draft (`cmd/api`, `internal/{config,apperr,transport,service,store,validator,replay,daily}`), но на стандартном `http.ServeMux` с методами в шаблонах — внешних зависимостей нет. Маршруты:
  - `GET /healthz`;
  - `GET /v1/daily` — дата и сид дня (день по UTC);
  - `POST /v1/daily/replays?player=ID` — тело = текст реплея;
  - `GET /v1/daily/leaderboard` — топ-20.
- **Правила дейлика — в симе** (`sim/DailyRules.cs`): отряд дня по сиду, полный забег, тир 0, нулевая мета, без оверрайдов. Валидатор сверяет отпечаток конфига реплея с каноническим, поэтому «облегчённый» дейлик (короткий акт, `maxEnemies=1`) не пройдёт. Сервер делает только дешёвый предотсев (формат, сид дня) и не знает версию баланса — чужую отвергает валидатор.
- **Валидатор** — `glimmerfall-sim verify --json - [--daily ГГГГ-ММ-ДД]`: реплей в stdin, вердикт JSON-строкой; очки считает `Rules.RunScore` после ре-симуляции, клиентские очки не принимаются. `validator/Dockerfile` упаковывает это в образ (`sdk:10.0.403` → `runtime:10.0.14`).
- Сид из строки — FNV-1a по UTF-16 в C# и в Go; вектор `daily-2026-10-26 → 4973729189407420658` совпал в обоих языках.

## Доказательства
- `go test ./...`: дата по UTC, совпадение сида с C#, разбор заголовка golden-реплея, таблица (лучшая запись игрока, тай-брейк по тикам), HTTP-маршруты с отказами 400/413/422 и **интеграция с настоящим .NET-валидатором**: записанный ботом дейлик проходит, тот же реплей для другой даты и с подменённым дайджестом — отвергаются.
- Сквозной прогон: кайтер сыграл дейлик 2026-10-26 (93 тыс. шагов, 26 минут игры, реплей 281 КБ), сервер принял его, ре-симулировал и поставил на 1-е место с 18 100 очками.
- Docker-образ локально не собирался (базовые образы не скачивались без согласия владельца) — его собирает и проверяет джоб CI `validator`.

## Ограничения каркаса
- Нет аутентификации: `player` — параметр запроса. Вход — через Steam (G1.6); до этого каркас не разворачивается публично.
- Таблицы в памяти одного инстанса; Postgres с миграциями — по образцу aegis-draft (goose + pgx), когда появится развёртывание.
- Реплей доказывает, что забег легален по правилам, но не то, что его играл человек: бот с идеальным вводом даст валидный реплей. Защита — вне валидатора (аномалии, ручная модерация топа).
- Ре-симуляция 26-минутного дейлика заняла около 10 с на одном ядре M1 Max; очередь воркеров и лимиты — при развёртывании.
